# tickoff v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the tickoff v1 PWA: personal and shared lists with Comprar/Hacer tabs, stores, history with revert, in-app activity notifications, offline support and export to Google Drive, on Firebase Spark.

**Architecture:** Client-only React app. Firebase Auth (Google) + Firestore (with persistent offline cache) is the only backend; all authorization lives in `firestore.rules`. Pure logic lives in `src/domain/` (unit-tested), Firestore reads/writes in `src/data/` as functions taking a `Firestore` instance (tested against the emulator), React hooks in `src/hooks/` wrap live listeners, screens in `src/screens/`.

**Tech Stack:** React 19, Vite 8, TypeScript, react-router (library mode), Tailwind CSS v4 (`@tailwindcss/vite`), shadcn/ui + lucide-react, Sonner, Motion, Geist (self-hosted), Firebase JS SDK (modular), vite-plugin-pwa, Vitest + Testing Library + jsdom, `@firebase/rules-unit-testing`, firebase-tools (emulators, deploy).

**Spec:** `docs/superpowers/specs/2026-10-20-tickoff-design.md`

## Global Constraints

- Run every command through mise (`mise x -- pnpm …`); pnpm only. Tool versions live in `mise.toml`; changing one also updates `engines` in `package.json` in the same commit.
- Add dependencies at their latest stable version with `pnpm add` / `pnpm add -D`; commit the lockfile.
- Firebase plan Spark only: no Cloud Functions, nothing requiring Blaze.
- UI copy in Spanish (México). Copy fixed by the spec is used verbatim: "Entrar con Google", "Comprar", "Hacer", "Terminar compra", "Archivar hechos", "Deshacer", "Compartir", "Nueva lista", "Sin categoría", "Todas", "Exportar JSON", "Exportar CSV".
- Item `kind`: `"buy" | "do"`. Item `status`: `"pending" | "done" | "closed"`. History `kind`: `"purchase" | "archive"`.
- Seed on first login: categories Despensa, Trabajo, Jardín, Mascotas; store "Super" (default); list "Despensa" in category Despensa.
- Invite: single use, expires 7 days after creation, revocable.
- Undo toast lasts 10 s.
- Activity `type`: `"added" | "done" | "closed" | "archived" | "deleted" | "joined" | "left"`. Activity is kept 30 days; grouping window 30 min.
- Drive scope is exactly `https://www.googleapis.com/auth/drive.file`; folder name `tickoff`.
- Item name: trimmed, 1–200 chars. Note and quantity: ≤200 chars.
- Writes to existing item docs use `updateDoc` with only changed fields, never `setDoc` over the whole doc.
- Closing/archiving never deletes item docs; it sets `status: "closed"` and `historyId`.
- Tests, fixtures and seeds use invented data only.
- Dev and tests use the Firebase emulators with project id `demo-tickoff`; no real Firebase project is needed until Task 15.
- Mobile-first layout; on desktop, content centered with max width ~480px.
- All UI follows `DESIGN.md` (created in Task 2). Use shadcn/ui components when one exists; icons from `lucide-react`, never emojis. Confirmations use `AlertDialog`; toasts use Sonner.

## Review Focus

1. **Product names that break Firestore doc ids** — a product named `1/2 kg jamón`, `.`, `..` or only spaces/accents. Expect: `productDocId` never returns an invalid id; blank names are rejected before any write. Test in Task 3.
2. **First login racing on two devices / reload mid-seed** — expect exactly one set of seed categories, one "Super" store and one "Despensa" list. Test in Task 5 (`ensureUserSetup` called twice concurrently).
3. **Invite link edge cases** — opened by the owner, by an existing member, after use, after expiry, after revoke, or with a garbage token. Expect a clear message on the Join screen and no write. Tests in Task 4 (rules) and Task 11 (`getInviteStatus`).
4. **CSV with commas, quotes, newlines and accents** — expect RFC 4180 quoting and a UTF-8 BOM so Excel opens "Jardín" correctly. Test in Task 14.
5. **Google login inside an installed iOS PWA** — popup may be blocked. Expect fallback to redirect. Test in Task 5 (`signIn` falls back to `signInWithRedirect` on `auth/popup-blocked` / `auth/operation-not-supported-in-this-environment`).

Each phase runs on its own branch off `main`, ends with a whole-branch review and a demo the user tries, and merges into `main` (merge, no rebase, no push) only after the user's OK. Update: owner may set `revoked: true`; joiner may set only `usedBy == auth.uid` and `usedAt` when currently unused, not revoked, not expired, and `getAfter(lists/{listId}).data.memberIds` contains `auth.uid`.
